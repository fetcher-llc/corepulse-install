**Trusted certificates with Let's Encrypt, without opening the server to the internet**

- Settings → Web certificate gets the site a free Let's Encrypt certificate by DNS challenge: choose your DNS
  provider, enter its key, save. CorePulse adds the proof record with the provider's API, so the server can
  stay private. Supported: Cloudflare, Amazon Route 53, Azure DNS, Google Cloud DNS, DigitalOcean, Hetzner,
  OVH, Gandi, Porkbun, DuckDNS, your own DNS server (RFC 2136), and acme-dns for any other provider. The page
  says where to create each provider's key. Renewals happen by themselves.
- The new setting is tried first in a separate copy of the web proxy. The site switches only once the
  certificate is in hand (within seconds); if it fails, nothing changes and the page shows the reason
  (for example the DNS provider's "Invalid access token").
- Or upload a certificate of your own (for example from your company's certificate authority); the page
  checks the key belongs to it.
- The key is kept in `.corepulse/tls/credentials.env` on the server, which only the web proxy gets. It is
  never stored in the database or shown again. The same from the server: `./corepulsectl certificate`.
  Changes from the page use the Upgrade now button's request folder and crontab line, now also on
  installs built from source; `./corepulsectl web-upgrades off` switches both off.
- IP addresses and local names keep CorePulse's own certificate. If anything is missing (no key, no
  files), the site falls back to CorePulse's own certificate rather than going offline.
- The page shows each name's certificate: issuer, end date, and whether browsers trust it.
  CorePulse checks every day and alerts you when a Let's Encrypt or own certificate has not been renewed.
- The web proxy is now CorePulse's own image (`corepulse-proxy`: Caddy with the DNS provider plugins).
  Like the other images it is scanned, signed and checked by `corepulsectl`. Upgrades from 0.10.x
  download it; its signature is checked from the next upgrade on.
