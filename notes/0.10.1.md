**One-click upgrades**

- Upgrade now on Settings → About: an admin enters their password and the server installs the newest
  release, the same way `./corepulsectl upgrade` does (signature checks, a backup first, automatic rollback),
  while a progress page follows it through the restart. On by default: a line in the install owner's
  crontab picks up the request within a minute (no root, no service); the web interface itself still has no
  access to Docker and can only ask for the newest version from the signed release list.
  `./corepulsectl web-upgrades off` switches it off for good.
- Servers upgrading from 0.10.0 or older: the upgrade itself is run by the older corepulsectl, so run
  `./corepulsectl web-upgrades on` once afterwards (the About page says so too).

**Fixed**

- The installer's DNS check no longer counts the server's own host name as known: the server answers it for
  itself, but other computers cannot use it (an install showed `https://corepulse-test` as its address). It
  asks the DNS server directly, so `/etc/hosts` entries do not hide or fake a name either.
- The web interface reads the same release list as `./corepulsectl` when `COREPULSE_UPDATE_URL` points at a
  mirror (it always read GitHub's).
